# 同车：先理解，再行动

更新：2026-10-24 · 当前原型 0.4 · 中英文纯文字 · Gemini 本机接入。

公开仓库保留当前 0.4 原型及设计说明；历史工作草稿保留在作者本地。

## 1. 已确认的核心

玩家首先在过自己的生活。另一个人进入视野，但双方完全陌生，玩家不知道他的身份、目的地和处境。

一些动作是在回应玩家，一些与玩家无关。玩家暂时分不清。系统则必须在动作发生前已有事实依据，不能在结尾补造原因。

关键节点分两次选择：

**NPC 开场观察与行动 → 玩家理解、行动 → NPC 观察、选择解释、预测、选择行动 → 玩家看到这个行动，再开始下一轮。**

双方交错进行。NPC 刚选择的动作就是玩家下一轮看到的动作，不再被节点预写动作覆盖。

普通过渡节点只选动作，避免每个细节都成为猜心题。

玩家解释不传给 NPC，不改变隐藏事实，不决定第二步的动作列表。相同动作可以来自不同理解；相同理解也可对应不同动作。

## 2. 场景与终点

夜间公交，陌生人通常不主动交谈。玩家坐在过道边，还有四站。靠窗的人没有名字，初始只呈现姿势与动作。

终点有两种，均无好坏评分：

- **确认联系：**明确向对方发起交流，对方确实注意并回应。当场结束，不继续介绍姓名、关系发展或后来成为朋友。
- **各自离开：**一方到自己的站下车，始终未确认联系。同样展示完整回看。

只让出一点空间、挪包、改变坐姿，不自动算搭上线。递东西并得到回应、明确问话并收到回答、对视点头并被回应，才算相互确认。

不为了保证固定长度禁止开口，也不为延长故事强迫 NPC 回避正常交流。

## 3. 当前可玩框架

最多八个节点，可能提前结束。初始人物处境从三组设定中选取并固定；回到旧节点保留同一组设定。

| 节点 | 可见事件 | 选择方式 |
|---|---|---|
| 坐下 | 玩家坐到过道边；NPC 决定开场动作 | 理解，再行动 |
| 倒影 | 车离站，窗上倒映两人 | 理解，再行动 |
| 刹车 | 车急刹；NPC 选择抓扶手或撑座椅 | 只行动 |
| 下一站 | 车停又开，过道空着 | 理解，再行动；可询问 |
| 脚边 | 小票从 NPC 口袋滑落 | 理解，再行动；可提醒或递还 |
| 站名 | 车内报站 | 理解，再行动；可点头或询问 |
| 空出的地方 | 有座位空出 | 理解，再行动 |
| 到站 | 玩家目的地到了 | 只行动；离开或道谢 |

节点是编排的框架，尚未实现完全自由生成的剧情。人物反应由模型在合法动作里临时选择，理解进入下一节点的角色状态。初始自身处境、既有物品、路线和结束边界不能被模型改写。

## 4. NPC 记录

每个实际完成的节点均保存：

1. 玩家看见的事情。
2. 玩家当时选择的解释，或标明此节点没有解释选择。
3. 玩家实际动作。
4. NPC 动作发生前的自身处境、注意与暂时理解。
5. NPC 在玩家行动后是否注意到，具体看见什么。
6. 三个候选解释及实际采用的一个；三个对玩家下一步行为的预测及实际采用的一个。
7. 当时合法的行动菜单、选中的行动、简短依据和实际执行结果。
8. 后来玩家实际做了什么，供比较预测；结束后的预测标明未被检验。
9. 本轮使用模型还是离线规则。

开场单独保存完整一轮。候选解释与预测由 Gemini 当轮生成，动作菜单由框架确定，Gemini 从中选择。

注意力约束：开场、明确交流、收包、挪脚、起身、换位等明显动作必须被注意；看窗外、安静坐稳、未处理小票等动作允许被忽略，但不能连续两轮都忽略玩家。注意到不等于正确理解，也不等于愿意搭话。

“没有注意到”“没有形成理解”是正常值。不能要求每一步都生成心理戏。这里的理解是简短的虚构角色状态，不是索取或展示模型完整的内部推理。

结尾按节点并排呈现玩家和 NPC 的两份记录，不算猜测正确率，不推断玩家人格。所有记录在过程中形成。可下载本局记录，也可回到旧节点重走；之前的记录不改写。

## 5. Gemini 分工与信息隔离

用户提供 Gemini 凭据并授权使用。本机服务使用 `gemini-2.5-flash`，该模型在实时可用模型列表中返回。

- 场景框架、开局隐情、候选动作及结束规则由游戏维护。
- 开场及每次玩家动作后的 NPC 注意、三个候选解释、三个候选预测、各自的选择和合法行动选择，交给 Gemini。
- 车辆行进、刹车、小票滑落、到站等外部事件由框架准备；不声称所有故事内容均由模型生成。
- 模型在当前姿势、场景和此前记录允许的动作内选择；温度设为 0.95 增加变化，不用均匀随机替代角色判断。刹车时菜单较短，到站离开等必然事件可能只有一个合法结果。
- 可见反馈使用与行动对应的短文本，防止模型用自由台词创造不存在的物件或延长已经结束的关系。
- NPC 只收到自己的处境、可见行为和已注意到的历史。玩家选择的解释不包含在请求中。
- 模型未注意到动作时，不允许编写观察记录或改变对玩家的理解。
- 相互确认必须同时满足玩家有明确指向对方的动作、NPC 注意到并选择回应。不能单靠“似乎关系变好了”结束。
- 请求失败或输出无效时不推进时间、不写入故事；页面允许重试或回到动作选择。不会静默改成离线结果。

本版仍是受约束的模拟，不是让模型随意写一篇小说。后续可进一步开放框架内的事件选择，但要保持事实一致与角色视角隔离。

## 6. 本地运行与凭据

凭据仅保存在本机服务进程内存，输入时不回显；不写入 HTML、脚本、存档、日志或文档。服务停止后需重新输入，或由用户自行配置环境变量。不要在文档中粘贴凭据。

页面能显示连接状态。通过普通静态文件或没有模型服务的地址打开时，明确标注离线规则试玩；只有连接到 Gemini 本机服务时才调用模型。2026-10-24 已发布中英文 0.4 原型，公开入口 https://along-the-way-jam-1023.fitcat.chatgpt.site 。Gemini 密钥作为托管服务端秘密配置，不进入网页或源代码。线上后端使用 Worker，保留模型结构验证及同源检查；按来源地址限制每小时请求次数（进程内尽力限制，并非严格费用上限）。

## 7. 测试与限制

自动检查覆盖 86 个规则状态、774 次选择；中英文覆盖 252 次转换一致性。检查交错回合、选项与选中项记录、私有解释隔离、注意力约束、非法动作拒绝、即时结束、历史保留及下一轮显示实际模型动作。

0.4 已进行中文真实 Gemini 多轮测试，开场及连续行动请求成功；模型实际选择了停留、看向玩家、抓扶手、往窗边让开等不同动作。中文实测在第四个节点问话后立即结束，复盘能展开三个不同候选解释并标记实际选择。规则测试不是模型人格质量或趣味性的证明。

实测也发现模型曾混淆包的归属、把后发生的刹车解释为先前动作的原因。已在输入中明确物品归属与先后顺序，并移除预写回复中无依据的“我以为你要出去”。这类语义一致性仍需持续试玩检查，结构验证不能完全消除。

模型存在随机性，因此不同实测结果不能直接证明是某个解释造成的。因果隔离通过请求边界和规则测试验证。

当前边界：少量预设初始处境、固定事件骨架、有限行动。模型表现和人物可信度仍需试玩检验。不要把规则通过或 API 成功等同于已经好玩。

## 8. 资料与历史

保留的创作问题：必须判断才能行动，但判断能否保持可修正？我们是否把对方独立发生的事情理解成对自己的回应？

不把主动交谈设成唯一正确结局，不把所有误会归因于玩家，不在结尾宣布 NPC 的观点是最终真相。

A 是理解玩家后调整回应；B 是采用玩家的通用策略。当前继续发展 A，双方反馈不要求策略模仿。


Gemini 接入依据：[官方 API](https://ai.google.dev/api)、[结构化输出](https://ai.google.dev/gemini-api/docs/generate-content/structured-output?hl=en)。

## 9. 英文版

新增英文入口 `http://127.0.0.1:8766/en.html`，标题 **On the Same Bus**。场景、解释、动作、结果、逐节点回看及 Gemini 的新记录均为英文；中文版本保留。页面顶端可以切换语言，切换会开始新的一局。

英文文件从同一份规则与翻译表生成，避免两份游戏逻辑各自漂移。更新后运行 `python3 prototype/build_languages.py` 及 `node prototype/test_languages.cjs`。0.4 已检查 252 次中英文状态转换一致。新版英文真实 Gemini 开场请求已验证成功；完整英文回合的规则与翻译由一致性测试覆盖。

观察记录直接引用被注意到的实际动作；模型提供是否注意及暂时理解，避免把 NPC 自己的动作误记给玩家。

## 10. 0.4 的设计边界

候选解释是虚构角色的当时判断，既不是客观真相，也不是模型隐藏思维的逐字转录。复盘不打分、不诊断人格。当前增加的是相互注意与交错判断的密度，不是保证每次动作都因玩家而起。

此版仍保留最多八个节点与三组开场处境。候选动作的短文本预先写好，Gemini 决定采用哪个；因此行为会变化，但不是完全自由生成的故事。0.3 代码与设计文档已保留在 archive，方便对照试玩。
